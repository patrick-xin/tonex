## The problem

Doing color well by hand is risky. Get one token wrong and the whole interface feels off, or fails contrast. So most products retreat to whatever feels safe, and everything converges on the same near-neutral look. Being distinct feels dangerous, so almost no one is.

## What Tonex does

You give Tonex one color. It derives a full system of semantic roles around it — backgrounds, accents, text, states — and checks every pair for contrast as you build. The result is coherent by construction, so you can be colorful without gambling on it.

The system is generative, not a preset. Change one digit of the seed and you get a different, still-coherent system; keep the seed and turn a knob and you get another. Your identity is a unique point in a continuous space, not a theme anyone can copy.

## Two ways to use it

- **Web app** — a visual editor. Set a seed, shape the system, preview it on real components, and export. Start at [Seed color](/docs/web-app/seed).
- **CLI** — one command from your terminal or an agent. Start at [Installation](/docs/cli/installation).

Both share one engine, so a seed produces the same system in either.
